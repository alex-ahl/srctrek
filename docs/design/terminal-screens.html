srctrek terminal screens

What trek shows in the terminal: the home screen and every state a change's trek can be in, the build view while an agent works, the route map of a whole trek, and stepping for editors without a plugin. Colours are the terminal's own: green, yellow, red, blue, and dim, as in the visual language.

1. The home screen

The change at the top, then what needs a decision (repos the agent proposed), then the change's trek, then every other trek. Enter opens the selected trek in the editor SRCTREK_EDITOR names.

2. Every state of the change's trek

The line under the header says where the change's trek stands and what the next key does about it.

◐ building feature-refunds 2:14
added s8–s14 · reading worker/main.py
enter watch the build · l log
An agent is building it; enter opens the build view.
● stale feature-refunds
4 of 19 steps' files changed since it was built
b update it · enter open it as it is
The branch moved on; updating keeps the steps whose files didn't change.
✕ build failed after 3 rejected rounds
s15: crosses from api to worker without citing worker
b build again · l whole log
The end of the log says why.
✕ can't open feature-refunds
repo worker isn't at ../worker
clone it there, or fix .srctrek/repos
A repo the trek names isn't where it was.
● older guide feature-refunds
built with an earlier trek guide
b rebuild with the current one · enter open it
The trek's prompt hash differs from this trek binary's.
○ no trek yet feature/refunds
set SRCTREK_AGENT to the command that runs your agent headless,
or ask your agent for a trek in chat
No agent configured.
○ nothing to trek

TRIGGERS IN web (trek --code)

command import-orders ○ enter build
Exploring code: its triggers, each with its trek's state.

3. The build view

Opened from a building trek. The overview as soon as the agent starts the trek, steps as they arrive, rejected rounds with their problems, and what the agent is reading.

4. The route map

The whole trek at once: one lane per repo, steps in the order they run, hops crossing between lanes, flags where they are. Enter opens the selected step in the editor; the map is the overview no single editor window can give.

5. Stepping without an editor plugin

The step view drawn in the terminal, for editors without a plugin: the code with the step's lines, narration, values, and signs, the call stack beside it. e opens the step in the user's editor at its line.

Questions for you

  1. The route map as lanes, one per repo, with hops crossing between them. Clear for two to four repos; with many repos it gets wide. Agree, or prefer a single list grouped by repo?
  2. The build view as its own screen, opened from a building trek, rather than growing inside the home screen. Agree?
  3. Stepping in the terminal for everyone, not only editors without a plugin: s on the home screen starts it anywhere. Useful for a quick look without opening the editor. Agree, or keep it as the fallback only?
  4. Proposed repos above the treks on the home screen, since they wait on the user. Agree?
