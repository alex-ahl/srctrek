Start a trek of the open change. `title` names what the change does in a few words, such as "Refunding an order"; `overview` says in a few sentences what the change does and what the trek follows; `trigger` is what starts the scenario (`kind`: request, event, schedule, or command; `input`: the concrete example, such as the request or command); `outcome` is what the scenario ends with. In both, mark the example's values with « and », such as `amount: «40»`. `sources` lists what else you read (specs, tickets, docs) as `{ kind, location }`; `author` names you (`agent`, `model`). Starting again replaces the draft. When building a trek, read trek_guide first.
